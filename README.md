# ACOS HTTP Proxy

Учебный многопоточный HTTP forward proxy на C++14 для Linux. Проект вручную
реализует работу с неблокирующими сокетами, `epoll`, `timerfd`, DNS-разрешением
имён и пулом потоков.

Прокси принимает HTTP-запрос от клиента, подключается к указанному в заголовке
`Host` серверу и возвращает клиенту полученный ответ.

```text
curl / браузер  ->  ACOS Proxy  ->  HTTP-сервер
                <-              <-
```

> Проект предназначен для обучения и экспериментов с сетевым программированием.
> В текущем состоянии его не следует размещать как публичный production-прокси.

## Возможности

- обработка нескольких соединений через Linux `epoll`;
- неблокирующие клиентские и серверные сокеты;
- поддержка HTTP-методов `GET` и `POST`;
- DNS-разрешение в отдельном пуле из 10 потоков;
- тайм-ауты соединений на базе `timerfd`;
- передача ответов с `Content-Length` и `Transfer-Encoding: chunked`;
- сборка и запуск в Docker без установки C++ toolchain на хосте;
- запуск процесса в контейнере от непривилегированного пользователя.

## Быстрый запуск через Docker

### Требования

- установленный и запущенный Docker Desktop или Docker Engine;
- свободный локальный порт `8080`.

### 1. Собрать образ

Из корня репозитория:

```bash
docker build -t acos-proxy:local .
```

### 2. Запустить прокси

```bash
docker run --rm --name acos-proxy -p 8080:8080 acos-proxy:local
```

Сервер работает в foreground. Отсутствие вывода после запуска нормально:
отладочное логирование в текущей конфигурации выключено.

Чтобы запустить контейнер в фоне:

```bash
docker run --rm -d --name acos-proxy -p 8080:8080 acos-proxy:local
```

### 3. Проверить работу

В другом терминале выполните HTTP-запрос через прокси:

```bash
curl -i --proxy http://localhost:8080 http://example.com/
```

Успешная проверка начинается со статуса:

```text
HTTP/1.1 200 OK
```

Проверить состояние контейнера:

```bash
docker ps --filter name=acos-proxy
```

Остановить foreground-контейнер можно сочетанием `Ctrl+C`. Фоновый контейнер
останавливается командой:

```bash
docker stop acos-proxy
```

Благодаря флагу `--rm` остановленный контейнер удаляется автоматически.

## Локальная сборка без Docker

Исходники используют Linux API `epoll`, `timerfd_create`, `pipe2` и `accept4`,
поэтому нативная сборка поддерживается только на Linux. На macOS и Windows
рекомендуется запуск через Docker.

### Требования для Linux

- CMake 3.0 или новее;
- компилятор с поддержкой C++14;
- POSIX Threads.

Для Debian/Ubuntu зависимости можно установить так:

```bash
sudo apt-get update
sudo apt-get install -y build-essential cmake
```

Сборка из корня репозитория:

```bash
cmake -S "Proxy Server" -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
```

Запуск на порту `8080`:

```bash
./build/server 8080
```

Порт является обязательным аргументом и должен быть свободен.

## Архитектура

Главный поток выполняет event loop и обрабатывает готовые файловые дескрипторы.
Потенциально блокирующая DNS-операция вынесена в отдельный пул потоков.

```text
                                      +----------------------+
                                      | DNS worker pool      |
                                      | getaddrinfo(), 10 шт.|
                                      +----------+-----------+
                                                 |
                                           notify pipe
                                                 |
+--------+      +--------------------+            v
| Client | <--> | epoll event loop   | <--> upstream HTTP server
+--------+      | client/server I/O  |
                +--------------------+
                         |
                      timerfd
```

Основные компоненты:

- `server.cpp` — точка входа и реализация жизненного цикла соединений;
- `proxy_server.h` — состояние прокси, клиенты, запросы, таймеры и DNS-очередь;
- `epoll_wrapper.*` — регистрация событий и диспетчеризация обработчиков;
- `client_and_servers.*` — RAII-обёртки файловых дескрипторов, сокетов и таймеров;
- `http_request.*` — разбор HTTP-запроса, заголовка `Host` и DNS-разрешение;
- `Executors/` — пул рабочих потоков для DNS-задач.

## Путь HTTP-запроса

1. `proxy_server` создаёт слушающий TCP-сокет на переданном порту и добавляет
   его в `epoll`.
2. После подключения создаётся объект клиента и `timerfd` для контроля тайм-аута.
3. Данные читаются неблокирующим сокетом до появления разделителя заголовков
   `\r\n\r\n`.
4. `http_request` проверяет метод, извлекает `Host`, определяет порт назначения и
   подготавливает запрос для upstream-сервера.
5. DNS-задача отправляется в `fixed_thread_pool`, где вызывается `getaddrinfo()`.
6. Рабочий поток записывает уведомление в pipe. Его читающий конец зарегистрирован
   в `epoll`, поэтому результат безопасно возвращается в главный event loop.
7. Прокси открывает неблокирующее соединение с upstream-сервером и пересылает ему
   HTTP-запрос.
8. Ответ читается до завершения тела, передаётся исходному клиенту, после чего
   соединение и связанные файловые дескрипторы закрываются.

## Настройка клиента

Для единичной команды достаточно параметра `curl --proxy`:

```bash
curl --proxy http://localhost:8080 http://example.com/
```

Также можно использовать переменную окружения только для текущей команды:

```bash
HTTP_PROXY=http://localhost:8080 curl http://example.com/
```

## Текущие ограничения

- поддерживается только обычный HTTP-трафик;
- HTTPS-туннели через метод `CONNECT` пока не реализованы;
- HTTP-парсер покрывает только базовые сценарии;
- нет аутентификации, правил доступа, кеширования и ограничения скорости;
- нет стабильного пользовательского логирования и метрик;
- нет автоматических unit- и интеграционных тестов;
- graceful shutdown и обработка части сетевых ошибок требуют доработки.

Для проверки используйте URL с `http://`, а не `https://`.

## Возможные следующие шаги

1. Добавить автоматические интеграционные тесты.
2. Исправить обработку частичных `read()`/`write()` и событий `EPOLLERR`/`EPOLLHUP`.
3. Добавить конфигурацию и структурированное логирование.
4. Реализовать HTTPS `CONNECT` как двусторонний TCP-туннель.
5. Добавить allowlist/blocklist доменов, статистику и ограничение запросов.
